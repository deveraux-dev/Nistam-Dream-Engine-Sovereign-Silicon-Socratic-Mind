     Harden the :13013 control-plane door

     Context

     "Harden my socket and IP 13013" traces to
     crates\forge-daemon-door\src\protocol.rs:9
     (DAEMON_ADDR = "127.0.0.1:13013") — the ForgeWire TCP control-plane door
     (crates\forge-daemon-door\src\door.rs, wire.rs, singleton.rs). This is NOT
     the
     NOTMAIL/spatial-memory-palace transport
     (crates\forge-comm-v3\src\transport.rs) —
     that crate ships zero network I/O by design (EphemeralChannel is a seam
     only, no
     relay client, ARCH000-gated future decision) — so there is nothing live to
     harden
     there yet.

     Receipted state of the real door (door.rs, wire.rs, singleton.rs, read this
     session):
     - Bound to 127.0.0.1 only — already not externally reachable
       (protocol.rs:9).
     - Whitelist::ALLOWED (door.rs:477-534) already enforces a read-only-verb
       allowlist before dispatch; mutating verbs (exec, shutdown, distill,
       hot_swap, etc.) are excluded from TOOL_TABLE's reachable set or
       explicitly
       refused (door.rs:794).
     - wire::read_header (wire.rs:117-143) already checks magic bytes and
       enforces
       MAX_FRAME_LEN = 4 MiB (wire.rs:28,134-139) — no unbounded-allocation DoS
       via
       a forged length field.
     - Gap 1: serve_listener (door.rs:802-823) spawns one unbounded OS thread
       per
       accepted connection with no cap — a local process opening connections in
       a loop
       exhausts threads/memory.
     - Gap 2: no set_read_timeout is applied to accepted streams in the
       production
       path — serve_frames's header read (door.rs:563, wire.rs:117-123) blocks
       forever on a connection that opens and sends nothing, holding its thread
       indefinitely (slowloris-shape). The idiom already exists in this same
       file's
       tests (door.rs:948,960,972,1013,1031,1101,1136 all call
       set_read_timeout(Some(Duration::from_millis(...)))) — it's just never
       applied
       to the real accept loop.
     - Gap 3: bind_singleton (singleton.rs:36-51) and serve_control
       (door.rs:829-833) bind whatever &str address is passed with no assertion
       that it's loopback — nothing today would stop a future call site from
       passing
       0.0.0.0:13013 and silently exposing the door to the LAN.

     Trust boundary: since the port is loopback-only, the threat model is "any
     other
     local process/user on this machine," not the network. The fixes below close
     local
     DoS and configuration-drift exposure without touching the whitelist, wire
     format,
     or adding an auth layer (adding real auth is a bigger ARCH000-class
     decision —
     flagged as out of scope, not silently done).

     Approach

     All changes are additive, in crates\forge-daemon-door\src\, reusing
     patterns
     already proven in this crate (no new dependencies — matches the project's
     near-zero-transitive-dep bar noted in singleton.rs:9-17).

     1. Loopback bind guard (singleton.rs)

     Add a small check at the top of bind_singleton (and serve_control,
     door.rs:829)
     that rejects (FATAL, exit 1 / Err) any addr not starting with 127.0.0.1: or
     localhost:, before the TcpListener::bind call. Cheap, defense-in-depth,
     matches the module's existing "singleton lock IS the safety mechanism"
     posture
     (singleton.rs:5-7) by adding one more invariant it enforces.

     2. Per-connection read timeout (door.rs::serve_listener)

     In serve_listener (door.rs:802-823), call
     stream.set_read_timeout(Some(Duration::from_secs(30))) right after stream
     is
     accepted and before cloning into writer/spawning the thread. 30s is
     generous for
     a legitimate local client but bounds how long an idle/hostile connection
     can pin a
     thread. Uses the exact idiom already proven at door.rs:948 etc.

     3. Bounded concurrent connections (door.rs::serve_listener)

     Add a process-global AtomicUsize connection counter (same OnceLock/static
     idiom as subscribers()/sessions(), door.rs:25-37). Cap at e.g. 64
     concurrent
     connections: on accept, if at cap, immediately close the stream (drop it)
     instead
     of spawning; decrement on thread exit via a guard (scopeguard-free — plain
     Drop impl or manual decrement at the end of the spawned closure, matching
     this
     file's no-new-deps posture).

     4. Tests

     Add to door.rs's existing #[cfg(test)] mod tests:
     - bind_singleton/serve_control reject a non-loopback address (e.g.
       "0.0.0.0:0") — assert Err/no listener created.
     - A connection that sends nothing gets closed by the server within the
       timeout
       window (bind ephemeral 127.0.0.1:0, connect, wait past timeout, assert
       the
       stream reads EOF/reset).
     - Opening cap+1 connections: the last one is refused/closed immediately
       rather
       than accepted.

     Explicitly out of scope

     - Adding authentication/authorization to the wire protocol
       (pubkey/session-token
       gating on every frame) — door.rs:31 documents "no auth" as an accepted
       in-memory-only design choice; changing that is an ARCH000-class call for
       Sean,
       not bundled into a hardening pass.
     - forge-comm-v3/NOTMAIL transport — no live network code exists there to
       harden
       (confirmed this session: transport.rs:71-84, seam only).
     - TLS — loopback-only traffic on a single machine; not a live threat this
       pass
       addresses.

     Verification

     - cargo test -p forge-daemon-door — new tests green, all existing tests
       (whitelist, orphan-detection, singleton, wire) still green.
     - Manual: start forgedaemon.exe, open >64 raw TCP connections to
       127.0.0.1:13013
       without sending data, confirm the daemon stays responsive to a fresh ping
       call
       and old idle connections get reaped after 30s.
